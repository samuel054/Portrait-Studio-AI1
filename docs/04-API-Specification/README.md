# API Specification

**Version:** 1.0  
**Status:** Draft  
**Owner:** Backend Engineering

## Standards

- REST over HTTPS
- JSON responses
- Multipart form-data for image upload
- Versioned routes under `/v1`
- OpenAPI generated by FastAPI

## Error format

```json
{
  "detail": "Human-readable error message"
}
```

## HTTP status conventions

| Code | Meaning |
|---|---|
| 200 | Successful request |
| 201 | Resource created |
| 400 | Invalid or corrupt input |
| 404 | Resource not found |
| 409 | Invalid workflow state |
| 413 | Upload too large |
| 415 | Unsupported media type |
| 422 | Validation or business-rule failure |
| 429 | Rate limit exceeded |
| 500 | Internal server error |
| 503 | Model runtime or dependent service unavailable |

- `refining`
- `rendering`

## Request rules

- Supported upload types: JPEG, PNG and WebP.
- Maximum upload size: 20 MB for MVP.
- Candidate count: 1-4; normal product flow should request 2-4.
- User-supplied model workflow files are prohibited.
- Refinement strength must remain within approved conservative limits.

## Response rules

- Candidate responses must contain stable IDs A-D.
- Rejected candidates must not be returned to the user-facing interface.
- Image payload metadata must include content type and filename.
- Large production image payloads should use short-lived object-storage URLs instead of Base64.

## Security requirements

- Validate file type, MIME type, size and decoded dimensions.
- Apply request and model-runtime timeouts.
- Restrict CORS to approved origins in production.
- Keep ComfyUI on a private network.
- Do not log raw image data or face embeddings.

## Versioning

Breaking contract changes require a new major API prefix. Additive changes may remain within `/v1` when backward compatible.

## Acceptance criteria

- Every implemented endpoint appears in OpenAPI.
- Requests and responses are schema validated.
- Error behavior is consistent.
- Core endpoints have automated API tests.
- Backward compatibility is maintained within the major version.
